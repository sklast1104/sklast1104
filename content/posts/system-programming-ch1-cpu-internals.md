> 시스템 프로그래밍 강의 내용을 정리한 노트임.

## 1. 시스템의 정의

"시스템 성능이 좋다"라고 하면 보통 CPU나 그래픽카드 같은 하드웨어를 떠올린다. 하지만 시스템 프로그래머 관점에서 시스템은 그보다 넓은 범위를 가짐.

| 구분 | 일반적 인식 | 시스템 프로그래머의 인식 |
|------|------------|----------------------|
| 구성 요소 | 하드웨어 (CPU, RAM 등) | 하드웨어 + 운영체제(OS) |
| 핵심 관점 | 물리적 장치 자체 | OS가 제공하는 기능으로 HW를 제어하는 환경 |

시스템 프로그래밍은 단순히 코드를 짜는 것이 아니다. Windows나 Linux 같은 OS가 하드웨어를 제어하기 위해 만들어둔 **API**를 충분히 활용하는 것이 본질이다. **OS를 모르면 하드웨어를 제대로 다룰 수 없다.**

## 2. CPU의 4대 핵심 구성 요소

CPU 내부에는 4가지 핵심 장치가 있다. 중요한 건 "무엇인가"보다 **"왜 필요한가"**다.

```
┌─────────────────────────────────────────────────┐
│                      CPU                         │
│                                                  │
│   ┌───────────────┐     ┌────────────────────┐  │
│   │  Control Unit  │     │     Register       │  │
│   │  (명령 해석)    │     │   (임시 저장소)     │  │
│   └───────┬───────┘     └─────────┬──────────┘  │
│           │   신호 전달            │  데이터 공급  │
│           ▼                       ▼              │
│   ┌──────────────────────────────────────────┐  │
│   │              ALU (연산 장치)               │  │
│   └──────────────────────────────────────────┘  │
│                                                  │
│   ┌──────────────────────────────────────────┐  │
│   │         Bus Interface (통신 중계)          │  │
│   └────────────────────┬─────────────────────┘  │
└────────────────────────┼────────────────────────┘
                         │
                 ┌───────┴───────┐
                 │  입출력 버스    │
                 └───────────────┘
```

### ALU (산술논리연산장치)

실제로 덧셈, 뺄셈 같은 산술 연산과 논리 연산을 수행하는 장치. CPU에서 실질적인 계산을 담당함.

### Control Unit (제어 장치)

이진 코드(Binary Code) 형태의 명령어를 해석하고, ALU에게 연산 신호를 보내는 장치. CPU 전체의 동작 흐름을 관리하는 사령탑.

### Register (레지스터)

CPU 내부의 초고속 임시 저장소.

**왜 필요한가?** ALU는 연산에 집중해야 한다. 그런데 외부에서 데이터를 무작정 밀어넣으면 데이터가 엉키거나 손실됨. 레지스터는 데이터를 미리 받아두고, ALU가 준비됐을 때 바로 꺼내 쓸 수 있게 하는 **버퍼** 역할을 한다.

> **핵심 질문**: RAM이 있는데 왜 CPU 안에 레지스터를 또 만들었을까?
> → CPU 내부 장치들이 외부로 나가지 않고도 가장 빠르게 데이터를 처리하기 위한 **최소한의 전용 공간**이 필요하기 때문이다.

### Bus Interface (버스 인터페이스)

입출력 버스는 자신만의 통신 규약(Protocol)이 있다. CPU가 외부 장치와 통신하려면 이 규약을 해석하는 번역기가 필요한데, 그것이 Bus Interface다. 사운드카드, 네트워크 카드 등 모든 I/O 장치도 마찬가지로 자신만의 인터페이스를 가지고 있음.

## 3. 명령어 실행 과정: '2 + 5' 연산의 여정

`A.exe`를 실행해서 `2 + 5` 명령을 내렸다고 가정하자. 이 데이터가 어떤 과정을 거치는지 따라가보면:

```
    HDD/SSD            RAM                     CPU
  ┌─────────┐    ┌───────────┐    ┌──────────────────────────┐
  │  A.exe  │───▶│  2, 5     │───▶│  Bus Interface           │
  │         │    │  ADD 명령  │    │         │                │
  └─────────┘    └───────────┘    │         ▼                │
                                   │    Register              │
    ① 메모리 로드                  │    [2] [5] [ADD]         │
                                   │         │                │
    ② Fetch                       │         ▼                │
                                   │    Control Unit          │
    ③ Decode                      │    "ADD구나!" ──신호──┐  │
                                   │                      │  │
    ④ Execute                     │                      ▼  │
                                   │         ALU              │
                                   │       2 + 5 = 7         │
                                   │         │                │
                                   │         ▼                │
                                   │    Register [7]          │
                                   └──────────────────────────┘
```

1. **메모리 로드**: HDD에 있던 명령어와 데이터(2, 5)가 **RAM**으로 올라옴
2. **Fetch (유입)**: Bus Interface가 통신 규약에 맞춰 RAM의 데이터를 읽어 Register에 저장
3. **Decode (해석)**: Control Unit이 Register의 명령어를 가져와 해석. "이건 덧셈이구나" 판단 후 ALU에 연산 신호를 보낼 준비
4. **Execute (실행)**: ALU가 Register에 대기 중이던 2와 5를 가져와 계산. 결과값 7은 다시 Register에 보관

이 과정(Fetch → Decode → Execute)이 **1초에 수억 번** 반복된다. 한 치의 오차도 없이 동작하는 이유는 다음 섹션에서 설명함.

## 4. 클럭 신호 (Clock Signal)

CPU 내부의 모든 장치는 **클럭 신호**라는 공통된 박자에 맞춰 동작한다.

### 클럭이 없으면 어떻게 되는가?

```
장치 A (초당 10회 전송)  ──▶  장치 B (초당 5회 수신)

A가 보낸 데이터 #3이 도착했는데 B는 아직 #2를 처리 중
→ #2가 #3으로 덮어쓰기(Overwrite) → 데이터 손실
```

속도가 다른 장치들이 제각각 움직이면 데이터가 충돌하거나 유실된다.

### 동기화(Synchronization)

클럭 신호는 모든 장치를 같은 타이밍에 맞춰 동작하게 만든다. 오케스트라의 지휘자처럼 "지금!" 이라는 박자를 제공해서, 데이터 손실 없이 안전하게 정보를 주고받을 수 있게 함.

### 성능과 안정성의 트레이드오프

| 클럭 속도 | 장점 | 단점 |
|-----------|------|------|
| 높음 (빠른 박자) | 처리 속도 빠름 | 발열 증가, 시스템 불안정 |
| 낮음 (느린 박자) | 안정적, 저발열 | 처리 속도 느림 |

시스템은 보통 연결된 장치 중 **가장 느린 장치의 클럭에 맞추거나**, 안정적인 범위 내에서 동작하도록 설계됨.

## 5. 핵심 정리

| 개념 | 내용 |
|------|------|
| **시스템** | 하드웨어 + 운영체제. OS API를 활용해 HW를 제어하는 환경 |
| **ALU** | 실제 산술/논리 연산 수행 |
| **Control Unit** | 명령어 해석, ALU에 연산 신호 전달 |
| **Register** | ALU 전용 초고속 버퍼. RAM과 별도로 존재하는 이유: CPU 내부에서 최소 지연으로 데이터 접근 |
| **Bus Interface** | 입출력 버스의 통신 규약을 해석하는 번역기 |
| **클럭 신호** | 모든 장치를 동기화하여 데이터 손실 방지 |
| **Fetch-Decode-Execute** | CPU가 명령어를 처리하는 기본 사이클 |
