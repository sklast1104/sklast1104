> 이 글은 GDC 2015 발표 "Guilty Gear Xrd's Art Style"과 직접 수행한 분석 결과를 바탕으로 작성되었습니다.

## 1. 서론

길티기어 Xrd는 3D 게임임에도 불구하고 2D 셀 애니메이션과 구분이 어려울 정도의 비주얼을 구현했다. 특히 주목할 점은 캐릭터의 내부 라인(Inner Line) 처리 방식이다.

일반적인 3D 게임에서 카메라를 캐릭터에 근접시키면 텍스처의 계단 현상(Aliasing)이나 블러링이 발생한다. 그러나 길티기어의 라인은 확대 배율에 관계없이 선명함을 유지한다.

본 글에서는 이를 가능하게 하는 **UV 트릭** 과 그 기반이 되는 **무게중심 좌표(Barycentric Coordinates)** 에 대해 분석한다.

---

## 2. 텍스처 기반 방식의 한계

### 해상도의 제약

텍스처는 본질적으로 비트맵 이미지이며, 해상도가 고정되어 있다. 1024x1024 또는 4K 해상도를 사용하더라도 근접 촬영 시 픽셀이 노출되는 것은 불가피하다.

```
이상적인 곡선:            실제 렌더링(확대 시):
    ╭───╮                ┌─┬─┬─┬─┐
   ╱     ╲               │█│ │ │ │  ← 픽셀 노출
  │       │      →       ├─┼─┼─┼─┤
   ╲     ╱               │ │█│ │█│  ← 계단 현상(Aliasing)
    ╰───╯                └─┴─┴─┴─┘
```

길티기어는 컷신에서 캐릭터 얼굴을 화면 전체에 채우는 연출을 자주 사용한다. 이러한 상황에서 텍스처 기반 방식은 품질 저하가 불가피하다.

---

## 3. 해결책: 실시간 계산 방식

Arc System Works가 채택한 방식은 라인을 텍스처에 저장하는 대신 실시간으로 계산하는 것이다. 이는 벡터 그래픽의 원리를 3D 메시에 적용한 것으로, **UV 트릭** 이라 불린다.

### UV 트릭의 구현 원리

1. 라인을 표현할 영역의 메시 구조를 설계한다.
2. 라인의 한쪽 끝 버텍스에 UV 값 `0.0`, 반대쪽에 `1.0`을 할당한다.
3. 셰이더에서 UV 값이 `0.5`인 지점에 라인 색상을 적용한다.

이 방식은 텍스처 해상도와 무관하게 수학적으로 정확한 라인을 생성한다.

---

## 4. 이론적 배경: 무게중심 좌표

### GPU의 삼각형 래스터라이제이션

3D 렌더링에서 모든 폴리곤은 삼각형으로 분할된다. GPU가 삼각형 내부를 래스터라이즈할 때, **무게중심 좌표(Barycentric Coordinates)** 를 사용하여 정점 속성을 보간한다.

![라인 렌더링 분석 다이어그램](images/posts/guilty-gear-rendering/analysis-diagram.png)
*라인 렌더링의 데이터 흐름. 중앙의 보간(Interpolation) 과정이 핵심이다.*

### 수학적 정의

삼각형의 세 정점을 $A$, $B$, $C$라 할 때, 삼각형 내부의 임의의 점 $P$는 다음과 같이 표현된다:

$$P = uA + vB + wC$$
$$(단, u + v + w = 1)$$

### UV 트릭에서의 활용

1. 아티스트가 정점 $A$에 UV 값 `0`, 정점 $B$에 UV 값 `1`을 할당한다.
2. GPU는 삼각형 내부를 래스터라이즈하면서 무게중심 좌표에 따라 UV 값을 `0`에서 `1`로 보간한다.
3. 결과적으로 삼각형 내부에 UV 값이 정확히 `0.5`가 되는 등고선이 형성된다.
4. 셰이더는 해당 등고선 위치에 라인을 렌더링한다.

이 라인은 이미지 데이터가 아닌 수학적 계산의 결과물이므로, 확대 시에도 품질 저하가 발생하지 않는다.

---

## 5. 셰이더 구현 예시

다음은 UV 트릭의 기본 원리를 구현한 셰이더 코드이다.

```hlsl
half4 frag(Varyings IN) : SV_Target
{
    // GPU가 무게중심 좌표로 보간한 UV 값
    float t = IN.uv.x;

    // 라인 두께 계산 (화면 공간 미분 활용)
    float halfWidth = fwidth(t);

    // t가 0.5 근처일 때 라인 알파 값 생성
    // smoothstep으로 안티에일리어싱 처리
    float lineAlpha = smoothstep(0.5 - halfWidth, 0.5, t)
                    - smoothstep(0.5, 0.5 + halfWidth, t);

    return lerp(_BaseColor, _LineColor, lineAlpha);
}
```

---

## 6. 결론

길티기어의 라인 렌더링 품질은 고해상도 텍스처가 아닌, 3D 렌더링 파이프라인의 보간 메커니즘을 활용한 결과이다.

2D 스타일을 구현하기 위해 3D 그래픽스의 수학적 원리를 역이용한 점이 이 기법의 핵심이라 할 수 있다.
