> **참고**: 이 글은 GDC 2015 발표 *"Guilty Gear Xrd's Art Style"*과 최근 수행한 역분석(Reverse Engineering) 결과를 바탕으로 재구성했습니다.

## 1. 서론: "이게 3D라고?"

길티기어 Xrd가 처음 나왔을 때 다들 기억하시나요? 충격 그 자체였죠.
분명 3D 게임인데, 아무리 봐도 완벽한 2D 셀 애니메이션처럼 보였으니까요.

특히 개발자들을 미치게 만든 건 **'선(Line)'**이었습니다.
보통 3D 게임에서 카메라를 캐릭터 얼굴에 갖다 대면 어떻게 되나요? 텍스처가 자글자글해지거나(Aliasing), 뿌옇게 뭉개지죠. 그런데 길티기어는?

**절대 안 깨집니다.** 카메라가 콧구멍 앞까지 가도 라인이 칼같이 살아있어요. 마치 벡터 이미지처럼요.
오늘은 그 비밀인 **UV 트릭**과, 그 뒤에 숨겨진 수학적 원리인 **무게중심 좌표(Barycentric Coordinates)** 이야기를 해보려 합니다.

---

## 2. 왜 텍스처로 그리면 망하는가?

가장 직관적인 방법은 그냥 텍스처(UV 맵)에 선을 그리는 거겠죠. 하지만 이 방식은 치명적인 단점이 있습니다.

### 텍스처는 '해상도'가 있다
텍스처는 결국 비트맵 이미지입니다. 1024x1024든 4K든 한계가 있죠.
카메라가 멀리 있을 땐 괜찮지만, 클로즈업 하는 순간...

```
현실의 곡선:              디지털 화면(확대 시):
    ╭───╮                ┌─┬─┬─┬─┐
   ╱     ╲               │█│ │ │ │  <-- 픽셀이 튀기 시작함
  │       │      →       ├─┼─┼─┼─┤
   ╲     ╱               │ │█│ │█│  <-- 계단 현상(Aliasing) 지옥
    ╰───╯                └─┴─┴─┴─┘
```

길티기어처럼 컷신에서 얼굴을 화면 가득 채우는 연출을 하려면, 텍스처 방식으로는 답이 없습니다. 8K 텍스처를 써도 모자랄 테니까요.

---

## 3. 해결책: "그리지 말고, 계산하자"

아크 시스템 웍스의 변태 같은(칭찬입니다) 해결책은 이겁니다.
**"선을 텍스처에 그리지 말고, 실시간으로 계산해서 만들자."**

이게 무슨 소리냐고요? 벡터 그래픽(Vector Graphics)과 비슷한 원리를 3D 메시에 적용한 건데, 여기서 그 유명한 **UV 트릭**이 등장합니다.

### UV 트릭의 핵심 메커니즘

1.  선을 넣고 싶은 부위의 모델링(Mesh) 구조를 잡습니다.
2.  선의 한쪽 끝 버텍스 UV를 `0.0`, 반대쪽을 `1.0`으로 줍니다.
3.  **가운데 텍스처는? 필요 없습니다.**
4.  셰이더에서 "UV가 0.5인 지점에만 색을 칠해라"라고 명령합니다.

이렇게 하면 텍스처 해상도와 상관없이, 수학적으로 완벽한 곡선이 나옵니다.

## 4. 심층 분석: 삼각형의 무게중심 (Barycentric Coordinates)

자, 여기서 조금 더 깊게 들어가 보죠.
제가 최근에 이 기법을 역분석하면서 학위 논문 마냥 뜯어본 내용이 있는데, 사실 이 기법이 가능한 진짜 이유는 **GPU가 삼각형을 그리는 방식** 그 자체에 있습니다.

![라인 렌더링 역분석 데이터](images/posts/guilty-gear-rendering/analysis-diagram.png)
*직접 분석해본 라인 렌더링의 데이터 흐름입니다. 중앙의 보간(Interpolation) 과정이 보이시나요?*

### 삼각형 안에서 일어나는 마법

우리가 3D 게임에서 보는 모든 면은 삼각형(Triangle)입니다. GPU가 이 삼각형 내부를 칠할 때(Rasterization), 가장 먼저 하는 일이 **보간(Interpolation)**입니다.

이때 사용되는 수학적 개념이 바로 **무게중심 좌표(Barycentric Coordinates)**입니다.

*   삼각형의 세 꼭짓점 $A, B, C$가 있다고 칩시다.
*   삼각형 내부의 어떤 점 $P$도, 이 세 점의 '가중치 합'으로 표현할 수 있습니다.
    $$P = uA + vB + wC$$
    $$(단, u + v + w = 1)$$

### 이게 왜 중요하냐고요?

길티기어의 라인은 붓으로 그은 게 아닙니다. 이 **무게중심 좌표계 위에서 줄타기를 하는 것**입니다.

1.  아티스트가 버텍스 $A$에는 UV `0`, 버텍스 $B$에는 UV `1`을 줍니다.
2.  GPU는 삼각형 내부를 칠하면서 이 무게중심 좌표에 따라 UV 값을 `0`에서 `1`로 부드럽게 섞어줍니다(Center Interpolation).
3.  그 결과, 삼각형 한가운데에 정확히 `0.5`가 되는 **보이지 않는 등고선**이 생깁니다.
4.  셰이더는 그 등고선을 찾아 선을 긋는 거고요.

즉, 이 선은 이미지 데이터가 아니라 **수학적인 '무게중심의 평형점'**에 그려지는 겁니다. 그래서 아무리 확대해도 깨질 수가 없는 거죠. 데이터가 아니라 수식이니까요.

## 5. 셰이더로 구현한다면?

이걸 코드로 짜보면 생각보다 심플합니다. (물론 실제론 더 복잡하지만 원리는 이렇습니다)

```hlsl
half4 frag(Varyings IN) : SV_Target
{
    // GPU가 무게중심 좌표로 이쁘게 보간해준 UV 값
    float t = IN.uv.x; 

    // 선의 두께 결정 (화면 해상도 기반으로 조절하면 더 좋음)
    float halfWidth = fwidth(t); 

    // t가 0.5 근처일 때만 1.0(검은색)을 반환
    // smoothstep을 써서 안티에일리어싱 처리
    float lineAlpha = smoothstep(0.5 - halfWidth, 0.5, t) 
                    - smoothstep(0.5, 0.5 + halfWidth, t);

    return lerp(_BaseColor, _LineColor, lineAlpha);
}
```

## 6. 마치며

결국 길티기어의 그래픽이 쩌는 이유는 텍스처를 잘 그려서가 아니라, **3D 렌더링 파이프라인의 본질(보간)**을 완벽하게 이해하고 응용했기 때문입니다.

"2D처럼 보이게 하기 위해 가장 3D스러운 수학을 썼다"는 게 아이러니하면서도 멋지지 않나요?
